# 模板与配置边界

## 后续定制的最短工作流

1. 收集照片、孩子画作或旅行素材，并选出 5–8 个关键故事节点。
2. 整理成“每幕一句主题 + 一段旁白 + 纸片清单 + 动效清单”。
3. 先定一张人物风格锚点，再批量生成同一角色需要的姿态或服装版本。
4. 建筑、人物、树、云和道具分别生成透明纸片，不把整幕烘成一张背景图。
5. 把素材路径、位置、大小、层级和动效写进 `story.config.js`。
6. 运行 `npm run verify`，再用浏览器验收每幕、首尾循环和手机画面。

## 固定模板层

| 固定能力 | 当前实现 |
| --- | --- |
| 镜头与舞台 | 镜头沿横向纸张曲线移动，舞台首尾连续 |
| 无限循环 | 前、中、后三份曲线接力，终幕直接连回下一轮首幕 |
| 纸张世界 | Three.js 程序化作业本几何、灯光和阴影 |
| 输入 | 滚轮、横向拖动、方向键、章节跳转 |
| 声音 | 可选的程序化 Web Audio，不依赖音乐文件 |
| 响应式 | 桌面和窄屏共用同一舞台，叙事纸条自动收紧 |

## 每单配置层

| 配置 | 例子 | 是否写引擎代码 |
| --- | --- | --- |
| 故事和章节 | 标题、旁白、人物名单 | 否 |
| 角色版本 | `arrival` / `journey` / `celebration` | 否 |
| 纸片资产 | `character-a.webp`、`tree-a.webp` | 否 |
| 布景 | `position`、`height`、Z 层级 | 否 |
| 局部动画 | 为当前故事注册的 `float`、`sway`、`reveal` 等预设 | 否 |
| 节奏与视角 | 阈值、舞台间距、滚动灵敏度、FOV | 否 |
| 纸张外观 | 页面颜色、横线、折边、车道 | 否 |

## 需要扩展引擎的情况

- 新增未覆盖的交互，例如点击打开相册、语音留言或烟花。
- 需要嘴型、面部表情或复杂拥抱动作；优先考虑透明序列帧或多层纸偶。
- 舞台改成环形、上下楼或自由探索，需要新写程序化几何和镜头路径。
- 客户指定真实立体产品或建筑，可单独评估模型资产，但不要把它塞回通用模板依赖。

普通亲子、家庭或情侣纪念站应只改故事、纸片、配置和少量动效。空白模板不预装任何案例故事的角色或动画；模板的默认交付边界始终是浏览器原生 Three.js，不要求安装额外 3D 制作工具。
